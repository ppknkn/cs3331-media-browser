## 问题复现与修复验收条件

### CR01 大图集扫描截断

构造根目录包含 `AA/`、`ZZ/` 和 `zzz.jpg`，其中 AA 有 6 个图片文件，ZZ 有 1 个图片文件。以函数支持的 `limit=3` 参数执行扫描，返回的图集只有 AA，根媒体列表为空。AA 的 `partial` 为 true，提示达到扫描上限；ZZ 和 zzz.jpg 均消失。

原因是根目录枚举和每个图集的递归统计共同消耗一个预算，且根目录枚举暂停后先执行递归统计。第一个图集耗尽预算后，恢复根目录枚举立即退出。默认 100000 项预算只是提高触发规模，并没有改变逻辑。

修复应给当前层的可导航对象保留独立的枚举预算，使某个子图集统计截断不会隐藏其他同级入口。统计不完整的图集必须标明部分统计；当当前层本身超过上限时，应有清晰警告。扫描还需在读取目录条目时就保持有界，不能先将整个超大目录排序后再执行限制。

复评还检查了不完整计数的后续用途。晚序图集可能返回 `partial=true` 和零计数，这表示尚未统计到媒体；类型筛选若仍只看 `imageCount > 0` 或 `videoCount > 0`，会再次隐藏可能含有相应媒体的图集。不完整统计的图集应保留可进入的筛选入口，并保持部分统计提示。

首轮最小结果：

```text
budget=3 albums=["AA"] media=[] partial=[true]
```

### CR02 新图集加载期间的旧内容

在已有图集 A 内容的状态下进入图集 B，`loadFolder` 立即把 `state.path` 和面包屑更新到 B，但保留 A 的 `state.library`。请求期间搜索输入、类型筛选、排序或视图切换仍然可用，它们调用 `render`。`render` 使用 A 的内容重建卡片，同时将 `content.hidden` 设为 false。因此 B 的标题下会出现 A 的可点击卡片。

这项结论来自确定的源码执行路径；首轮未将浏览器慢请求截图作为实测证据。独立前端测试应延迟 B 的响应，再触发筛选或排序，验证响应到达前不会出现 A 的卡片；继续快速导航时，最后一次请求应决定最终内容。可在加载开始清空旧库状态，或让渲染受到加载状态与请求代次约束。

### CR03 Windows 目录联接

实际执行环境为 Anaconda Python 3.10.20，该版本 `Path` 没有 `is_junction` 方法。创建 `AliasAA` 目录联接指向同一库内的 `AA`，扫描返回两个名称与路径都为 AA、计数都为 6 的图集：

```text
path_is_junction_available False
junction_scan [("AA", "AA", 6), ("AA", "AA", 6), ("ZZ", "ZZ", 1)]
```

`entry.is_symlink()` 未识别此 NTFS 目录联接，后面的兼容性判断又因方法不存在而跳过。路径解析后使用目标路径生成名称和图集地址，因而出现重复入口。README 宣称扫描跳过目录联接，与指定环境的实际行为不符。

修复需在 Python 3.10 也能识别目录联接或相关重解析点，保留所选目录边界和循环保护。独立测试应覆盖库内联接、库外联接及指向祖先的循环。首轮没有发现库外联接绕过 `resolve` 与 `relative_to` 边界的证据；重复图集不应被夸大为已证实的越界读取。

### CR04 HTTP 分段语义

对 10 字节的人工文件进行真实请求，首轮结果为：

| 请求 | 实际状态 | 实际长度与范围 | 期望 |
| --- | --- | --- | --- |
| `HEAD`，`Range: bytes=0-2` | 206 | `Content-Length: 3`，`Content-Range: bytes 0-2/10`，实体 0 字节 | 200、全长 10、无 Content-Range、无实体 |
| `HEAD`，`Range: bytes=99-100` | 416 | `Content-Range: bytes */10`，无实体 | 忽略 Range 后返回 200 全长头 |
| `GET`，`Range: items=0-2` | 416 | 返回 invalid_range | 未识别的范围单位应忽略，返回完整 200 |
| `GET`，`Range: bytes=0-1,4-5` | 416 | 返回 invalid_range | 此应用可明确忽略多段 Range 并返回完整 200，或实现多段响应 |

[RFC 9110 第 14.2 节](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)规定只有 GET 定义范围处理，服务器必须忽略其他方法收到的 Range，也必须忽略不认识的范围单位。两个合法、可满足的范围不能仅因应用只支持单段就当作文件范围不可满足。对本作业，忽略多段并返回完整媒体是清晰且兼容的策略。

修复后仍需验证有效单段的 206、越界单段的 416、后缀范围、开放结束位置、零长度文件、HEAD 无实体及 Content-Length 与实际 GET 实体长度一致。

### CR05 非 ASCII 令牌

发送 `POST /api/root`，请求头 `X-App-Token` 使用 HTTP 可表示的 Latin-1 字符 é，首轮返回 `500 internal_error`。`secrets.compare_digest` 的字符串比较只接受 ASCII；此输入抛出 TypeError，进入通用异常分支。

无效凭据应统一返回 `403 invalid_token`，不应改变目录或会话。独立测试应覆盖缺失、错误 ASCII、非 ASCII 令牌。

## 已审查的设计与边界

服务只监听 `127.0.0.1`；Host 校验同时检查主机、实际监听端口及用户信息、路径等异常成分。Origin 必须对应本机源，跨站 Fetch 被拒绝；修改根目录和打开选择器还要求随机令牌。静态路由是固定清单，任意工程文件没有通用静态读取入口。

媒体路径在转换为本地路径前拒绝上级目录、绝对路径、反斜杠、盘符和空字符，解析后的目标仍需位于根目录内。当前代码不提供媒体修改接口。文件名、目录名和错误消息使用文本节点；唯一的 innerHTML 来自不可变的作者 SVG 常量，未发现用户文件名直接插入 HTML 的路径。

根切换会生成新的 session。图集扫描、媒体读取和原生选择器返回结果都有会话检查；并发根切换在状态锁内再次比较会话，防止较旧的选择覆盖较新的选择。选择器忙碌状态在 finally 中恢复，取消保留当前目录，子进程有超时。

JSON 请求要求合适的内容类型，长度不超过 8192 字节，非对象 JSON 被拒绝；错误修改请求关闭连接，避免未消费请求体被解释为下一条请求。媒体流按块输出，客户端断开与文件缩短会结束连接。正式测试仍需独立覆盖非法 JSON、超大请求、请求读取超时和文件变动分支。

查看器使用原生 dialog 管理模态与焦点，打开时聚焦关闭按钮。Esc、关闭、切换项目与目录导航均调用媒体清理；视频会 pause、移除 src 并 load，避免继续播放。图片和视频错误都有可见提示，视频文案区分容器识别与编解码支持。搜索范围在空结果说明中写明为当前层。

主控 Agent 负责真实浏览器操作与响应式截图；TestEngineer 负责源码读取、单元测试及终端执行。原生目录对话框的真人点击不能用替身测试替代。本报告不将上述后续工作记为已完成。
