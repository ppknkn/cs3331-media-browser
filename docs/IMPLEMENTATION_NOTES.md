# CodeWriter 实现记录

本文件记录实现过程中的实际决策，供后续评审、测试报告和博客引用；不代表正式测试已通过。

- 使用 Python 3.10 标准库 `ThreadingHTTPServer` 与原生 HTML/CSS/JS。当前指定 conda 环境未安装 Flask，因此避免增加运行时依赖，也让代码在教学评审中可直接阅读。
- 选择 localhost 服务而非纯静态网页，是为了通过本机文件夹选择器访问本地目录，并按浏览器 `Range` 请求流式读取视频。网页无法在未经授权时任意读取本机文件。
- 所有根目录切换都需要同源 bootstrap 发放的随机操作令牌；Host/Origin 与浏览器 Fetch Metadata 限制跨站请求。服务只绑定 `127.0.0.1`。
- 根目录和 session 使用锁保护；扫描在锁外完成以避免阻塞其他浏览操作，响应返回前验证 session。URL 包含 session，使旧图集中的媒体链接不能用于读取新根目录。
- 文件夹路径接口只接受相对 POSIX 路径并拒绝 `..`、Windows 盘符、反斜线和绝对路径。最终路径必须 resolve 到当前根目录内。静态文件由固定路由表提供，不能通过路径获得服务器源码。
- 文件夹选择器使用独立 Tk 子进程；HTTP 工作线程不持有 GUI 主循环。取消和 90 秒超时均有明确响应，当前机器不具备 GUI 时可输入绝对路径。
- 子文件夹图集的数量包含其可读取的后代媒体。递归使用迭代栈及已访问集合，跳过符号链接，限制单次递归统计为 100000 项，并返回扫描不完整提示；当前层级的目录与媒体发现使用独立的 100000 项上限。目录迭代先有界采样再排序，不创建数据库或隐式修改媒体。
- 图片网格使用原始图片 lazy loading，避免运行时图像库依赖；不生成缓存缩略图。高分辨率照片很多时，首次图集浏览会增加本机解码开销。视频网格不自动预加载，点击后才进入原生播放器。
- 浏览器决定实际编码支持。扩展名识别只是候选媒体列表；MOV、AVIF 等可能在部分浏览器解码失败，界面提示编码局限，不伪造“所有格式可播放”。
- 前端文件名、路径、搜索结果使用 `textContent` 和 DOM 创建，避免把本机文件名当 HTML 解释。只用固定常量 SVG 插入 authored icons。
- 前端目录请求采用 `AbortController` 和请求序号，切换目录时废弃旧响应；查看器使用原生 `dialog` 管理模态焦点，支持左右切换、Escape、适应窗口与缩放。
- 视觉使用米白背景、暖陶色按钮、深墨绿文字，桌面侧栏与内容网格；窄屏收起侧栏，保留打开目录和核心浏览操作。支持浅深外观、列表与网格视图、减少动画偏好。

## 已知边界

- 服务用于单机个人浏览；没有远程访问、账户、多用户共享或上传功能。
- 任意软件只要已经以用户权限运行，通常可访问同一用户的本机文件；本服务边界不能替代操作系统权限。
- 扫描和媒体打开之间存在文件被用户移动/删除的情况，API 与查看器处理失效提示。
- session 切换后不会继续接受旧媒体 URL；已开始发送的媒体请求可能直到浏览器取消或传输结束才释放文件句柄。
- 搜索只筛选当前层级图集名称和媒体名称，不进行全库全文索引。
- 测试团队需要重点检查：Range/HEAD 与空文件、路径与来源边界、读取权限、并发切换 session、GUI chooser 取消/超时、文件名 XSS、真实视频解码与响应式布局。

## 首轮评审后的真实修复

CodeReviewer 指出以下三个 P2 问题，CodeWriter 核实源码后修复；正式回归测试由 TestEngineer 接手。

1. 顶层发现与后代媒体统计共用预算，靠前的大图集耗尽预算时，后续同层图集和媒体会消失。修复将当前层级发现从递归统计预算中分离。后代统计仍受预算约束，以 `partial` 与警告告知不完整计数；当前层级未超过自己的上限时，用户仍能看到并进入每个同层图集。
2. 请求新图集时只隐藏旧内容，搜索、排序、筛选事件仍可调用 `render` 展示旧 `state.library`，造成标题与图集不一致。修复在请求开始立即清理旧 `library` 和 `visibleMedia`，加载中工具栏事件不再渲染旧图集。
3. 最初 `HEAD` 和 `GET` 复用了 `Range` 解析，造成 `HEAD+Range` 返回 `206`。修复遵循 RFC 9110 第 14.2 节，仅对 `GET` 使用 `Range`；`HEAD` 返回 `200`、完整 `Content-Length` 且不发送响应体。

Reviewer 后续最小复现又确认 Windows Python 3.10 缺少 `Path.is_junction` 导致目录联接重复计数。扫描改为读取 Windows 文件的 reparse-point 属性，跳过目录联接；不能依赖开发机上不存在的较新标准库方法。

协议边界同步修正：未知范围单位及多段范围请求忽略 `Range` 返回完整 `200`，仍保留单段 `206` 与无效单段 `416`。操作令牌头先判断 ASCII，避免 `compare_digest` 对合法 Latin-1 请求头抛出异常；无效令牌返回 `403`。

复评还发现只在排序后扣除预算依然会先读取超大目录的所有条目。第二次修复以 `islice` 在读取阶段限制条目：递归每次最多读取剩余预算加 1 项，当前层每次最多读取其独立上限加 1 项，再排序已采样条目。多出的 1 项只用来判断截断，当前层截断另以顶层 `partial` 和中文警告报告。

复评同时检查了统计预算对前端筛选的影响：`partial` 图集的 0 计数不能当成确定不含图片或视频。类型筛选保留所有统计未完成的图集入口，卡片标明“已统计 N 项 · 总数未知”，进入后可继续浏览；顶层列表本身截断时，总数也加 `+`，避免展示为完整总数。
